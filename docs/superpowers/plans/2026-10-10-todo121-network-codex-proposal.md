# Codex independent proposal — 2026-10-10 Pacific
Written before Claude receives any Codex recommendation.

Scope: only the dashboard worker and compute children; preserve existing API/frontend loopback and authority/quota/archive UNIX-only limits. Bot-owned renew/size-check, token sync, public TLS reverse proxy and external Drive maintenance are separate services, not worker allowances.

Required HTTPS destination names (seven, not six): api.schwabapi.com, openrouter.ai, www.sec.gov, data.sec.gov, api.nasdaq.com, www.bing.com, news.google.com. Compute uses Schwab marketdata GET, OpenRouter POST chat completions, SEC mapping/submissions/archives GET, Nasdaq GET targets/info/earnings, and news GET feeds. No worker OAuth refresh (refresh_allowed=False); no arbitrary publisher links, Yahoo, Discord, Drive or localhost control HTTP is required. Keep existing UNIX quota/authority/gate sockets and local DB reads.

Prefer a small local forward CONNECT proxy with a distinct unprivileged identity and an exact seven-host:443 allowlist. Retain end-to-end TLS verification; no TLS interception or credential logging. Normalize/reject malformed CONNECT authorities, literal IPs, userinfo, alternate ports, wildcard domains and non-CONNECT methods. Resolve names at proxy, reject all non-public IPv4/IPv6 destinations, pin the vetted resolved address for each connection, revalidate each new connection; use bounded connections/bytes/timeouts. No destination discovery that automatically expands policy. Restrict proxy listener to a dedicated loopback TCP port selected after a port inventory; protect ingress to compute identity only.

Use systemd worker IPAddressDeny=any + localhost allowance inherited by compute, paired with dashboard-only per-UID nftables rules for both supervisor and compute: compute may reach only loopback proxy TCP port; supervisor may reach no IP destination. Cover IPv4 and IPv6 and existing established connections; restart worker after enforcing. Proxy may resolve via the local resolver and connect only public TCP/443; other dashboard services retain current rules. Do not apply host-wide rules. Prove nft UID matching and systemd cgroup-BPF availability in isolated tests first. If supervisor capabilities can escape this boundary, do not claim hostile-supervisor containment; review whether dropping capabilities after launch or a namespace is necessary. Objective is constrained provider egress, not a redesigned launcher.

Client changes: explicit reviewed proxy parameter in every aiohttp call path (SEC BudgetSession, news, street, assistant, synthesis); explicit requests proxies in isolated SchwabClient without trust_env=True. Preserve route quotas, retries, cancellation, policy fences and borrowed-token restrictions. Never change bot transport defaults. Need read provider_budget wrapper before coding. CONNECT enforces host/port only; HTTP method/path restrictions remain application-layer controls, not a network security guarantee.

Tests: allowed seven-host fixture TLS through proxy, real provider checks without weakening quotas, direct-IP/host/UDP/IPv6/alternate-loopback/redirect denial, malformed hosts and DNS-to-private denial, proxy outage fails closed, child restart/kill/cgroup inheritance, no secret logs, concurrency/feed/auth performance and bot unaffected. Record actual DNS/proxy connections across a market session: socket snapshot is not a complete connection inventory. Source failures alone must be distinguished from proxy denials. Staging before production mandatory.

Rollout: baseline live fingerprints and existing work; reproducible isolated Linux fixture; deploy clients with proxy wiring staged and smoke-test allowed paths; apply scoped rules and restart dashboard worker only in a short maintenance window; monitor through full market day. Stop on missing critical data, denied required destination, broken compute renewal, permission weakening or bot health change. No rollout until negative bypass tests and provider tests pass.

Rollback: back up exact touched files, unit/dropins and own nft table; restore only own matching changes, remove scoped table/dropin, daemon-reload and restart worker, recheck existing dashboard and bot. Keep proxy until reverted clients no longer reference it. Do not flush firewall or restart quota/authority/bot. Prefer cached dashboard mode over silently opening internet; emergency rollback to former unrestricted state must be explicit and documented.

Expected size: medium operational/security change, approximately 2–4 engineering days plus a full market-day observation. Work spans transport wrappers, one proxy/unit/policy, isolation tests and deployment docs, not a one-line unit edit. Alternatives: dedicated network namespace stronger but larger; IP allowlist alone brittle with shared CDN IPs; proxy variables alone bypassable.
